# 投注组合模拟双 Agent 设计

## 背景

当前系统已经支持世界杯赛程、体彩赛前情报、AI 预测、预测历史、模型排行榜和真实计分榜。最新实现将预测上下文默认切到体彩数据，并把最新预测摘要展示到赛程卡片。

现在的 P0 目标升级为：获取所有能从体彩公开接口和可用足球数据源获取到的信息，让 AI 不只预测比分，而是输出单场与多场串关的投注组合模拟方案。

本功能的产品文案统一使用“投注组合模拟”“风险预算方案”“赛前组合分析”。不使用“必中”“稳赚”“购买建议”“保证收益”等表述。所有输出必须包含风险提示、数据缺口和不下注条件。

## 当前问题

### 预测任务多选卡作用不足

当前 `PredictionRequestInputDto.taskTypes` 会进入 `prediction_context.taskTypes`，模型能看到用户选择了哪些任务。但后端 AI 输出结构固定，解析字段固定，因此多选卡目前只影响提示语，不会真正改变执行链、输出结构或 UI 展示。

需要把多选卡升级成执行控制：

- 勾选“赛果分析”时，只跑赛果分析 Agent。
- 勾选“单场组合”时，跑赛果分析 Agent 和单场组合 Agent。
- 勾选“串关组合”时，基于多场单场结果再跑串关 Agent。
- 勾选具体玩法时，输出中必须包含对应玩法判断。

### 当前体彩解析过窄

当前体彩解析主要抽取：

- `HAD`：胜平负，存在时解析。
- `HHAD`：让球胜平负。

真实 `getMatchListV1` 样例已确认 `oddsList` 中至少出现：

- `HHAD`
- `CRS`
- `TTG`

`CRS` 和 `TTG` 在样例中字段存在但赔率内容为空，需要继续针对可售场次抓取真实响应确认完整结构。实现时不得猜测字段含义，必须以抓包响应、测试样本或官方页面展示为准。

## 目标

### P0-1：单场双 Agent

每场比赛支持两个相互隔离的分析角色：

1. 赛果分析 Agent
2. 投注组合模拟 Agent

同一个模型可以调用两次，用不同提示词模拟不同 Agent，例如：

- `qwen` + 赛果分析提示词
- `qwen` + 投注组合模拟提示词

### P0-2：多场串关 Agent

串关 Agent 不重新预测比赛结果，只消费多场比赛的单场分析摘要和单场组合方案，输出多场组合模拟。

### 数据输入完善

提示词上下文应尽量包含：

- 比赛基础信息：球队、开赛时间、轮次、场馆、状态。
- 体彩全部玩法赔率：按接口真实返回保存，不只保存 `HAD` 和 `HHAD`。
- 历史交锋：交锋场次、胜平负比例、近期比分。
- 积分形势：排名、积分、小组出线压力。
- 近期状态：近期比赛比分和走势。
- 特征对比：胜率、主客表现等接口可用指标。
- 伤停信息：球员、位置、主客影响。
- 阵容信息：首发、替补、阵型；缺失时标记未获取。
- 球员信息：关键球员、位置、可用状态；缺失时标记未获取。
- 身价信息：球队总身价、核心球员身价、双方身价差；缺失时标记未获取。
- 模型历史表现：胜平负命中率、比分命中率、已结算场次；用于辅助展示模型可信度，不作为保证。

## 非目标

- 不承诺收益。
- 不接入真实下单。
- 不自动生成真实购彩单。
- 不根据赔率直接推导比赛结果。
- 不编造球员、阵容、身价、赔率、伤停或历史战绩。
- 不在 P0 中实现复杂资金管理、凯利公式或套利计算。

## 核心设计

### 数据层

体彩数据刷新时保存完整原始玩法，不再只生成一段摘要。

单场体彩玩法结构应表达：

- `poolCode`
- 玩法名称
- 选项列表
- 每个选项的显示名
- 每个选项的赔率
- 让球线或玩法附加线
- 更新时间
- 是否可用
- 原始数据片段

实现时先引入内部结构化对象，例如“玩法集合”，再由解析器生成：

- 给 UI 用的分段摘要。
- 给 AI 用的结构化 JSON。
- 给调试用的原始响应。

字段名必须来自真实响应或本项目新定义的 DTO，不能靠大小写或命名习惯猜测。

### Agent A：赛果分析 Agent

赛果分析 Agent 不负责投注组合，只负责足球判断。

输入：

- 比赛基础信息
- 历史交锋
- 积分形势
- 近期状态
- 特征对比
- 伤停信息
- 阵容信息
- 球员信息
- 身价信息
- 可选：体彩官方指数作为市场背景

输出：

- 胜平负倾向
- 参考比分
- 总进球区间
- 让球方向
- 关键理由
- 风险点
- 数据缺口
- 信心等级
- 不确定因素

约束：

- 官方指数不得替代足球判断。
- 对缺失数据必须写明“未获取”。
- 不输出投注组合。

### Agent B：单场投注组合模拟 Agent

单场投注组合模拟 Agent 消费赛果分析 Agent 的结构化结论和体彩全部玩法赔率。

输入：

- Agent A 的结构化输出
- 体彩全部玩法赔率
- 用户选择的玩法范围
- 用户选择的输出风格
- 风险约束

输出：

- 保守方案
- 均衡方案
- 激进方案
- 不下注条件
- 主要冲突点
- 数据缺口

每个方案包含：

- 方案名
- 风险等级
- 涉及玩法
- 选择项
- 组合逻辑
- 命中条件
- 主要风险
- 预算占比
- 说明文本

预算只输出占比，不输出鼓励性金额。默认比例可以是：

- 保守：50%
- 均衡：30%
- 激进：20%

如果数据不足或模型分歧大，必须允许输出“跳过本场”。

### Agent C：多场串关 Agent

串关 Agent 消费多场比赛的单场输出，不重新做比赛预测。

输入：

- 多场比赛的 Agent A 摘要
- 多场比赛的 Agent B 单场方案
- 每场风险等级
- 每场数据完整度
- 每场模型分歧情况

输出：

- 稳健串关
- 均衡串关
- 激进串关
- 避免组合
- 每组命中条件
- 串关风险说明
- 预算占比

P0 中支持：

- 2 串 1
- 3 串 1

更复杂串关类型留到后续。

## 预测任务多选卡改造

原有任务项应替换或扩展为：

- 赛果分析
- 比分预测
- 让球玩法
- 总进球玩法
- 比分玩法
- 半全场玩法
- 单场组合
- 串关组合

行为：

- 只选“赛果分析”：只跑 Agent A。
- 选择任一单场组合相关任务：跑 Agent A 和 Agent B。
- 选择“串关组合”：用户必须先选择多场比赛，再跑 Agent C。
- 玩法数据缺失时，UI 展示该玩法“未获取”或“不可用”，Agent 不得编造。

## 提示词框架

### 通用规则

- 只使用 `prediction_context` 中提供的数据。
- 对缺失数据写明未获取。
- 不承诺收益。
- 不使用“必中”“稳赚”等表述。
- 输出 JSON。
- 中文摘要必须可读。

### 赛果分析 Agent 提示词重点

- 先分析球队、阵容、伤停、状态、历史、身价。
- 再说明官方指数与足球判断是否一致。
- 官方指数只作为市场背景，不替代足球判断。
- 输出赛果、比分、总进球、让球方向和风险。

### 单场组合 Agent 提示词重点

- 以赛果分析 Agent 结论为主。
- 使用体彩全部玩法赔率构造组合。
- 说明每个组合的命中条件。
- 说明哪些玩法不建议选。
- 给出保守、均衡、激进方案。
- 给出跳过本场条件。

### 串关 Agent 提示词重点

- 从多场单场方案中选择低相关、风险可解释的组合。
- 避免把多个高风险激进项强行串在一起。
- 给出稳健、均衡、激进串关。
- 给出避免组合和原因。

## UI 设计

### 单场比赛卡片

展示最新模型摘要：

- 赛果倾向
- 参考比分
- 总进球区间
- 让球方向
- 推荐方案数量
- 风险等级

### 单场详情

使用 Tab：

- 赛果分析
- 体彩数据
- 单场组合
- 模型对比

### 串关工作台

新增串关入口：

- 选择多场比赛
- 选择串关类型
- 选择风险偏好
- 生成串关组合模拟
- 查看稳健、均衡、激进方案

## 后端接口设计

P0 可以先复用现有预测请求接口，但建议在实现计划中拆出更明确的执行结果结构。

需要新增或扩展：

- 单场预测运行结果中保存 Agent A 输出。
- 单场预测运行结果中保存 Agent B 输出。
- 串关运行结果中保存 Agent C 输出。
- 预测历史接口返回单场组合摘要。
- 可选新增批量最新组合摘要接口，避免赛程页逐场拉取历史。

数据库需要能保存：

- 结构化体彩玩法数据。
- 赛果分析 Agent 原始 JSON。
- 单场组合 Agent 原始 JSON。
- 串关 Agent 原始 JSON。
- 解析状态和错误信息。

## 数据缺失处理

所有数据域必须有明确状态：

- `cached`
- `unavailable`
- `refresh_failed`
- `not_requested`

当阵容、球员、身价数据未获取时：

- UI 显示未获取。
- prompt 中保留缺失标记。
- Agent 输出中必须说明数据缺口。

当体彩某玩法没有赔率时：

- UI 显示该玩法不可用。
- 单场组合 Agent 不得选择该玩法。

## 风险与合规边界

所有投注组合模拟必须包含：

- 风险等级。
- 数据缺口。
- 预算占比。
- 不下注条件。
- “仅供赛前分析和模拟，不保证结果”的提示。

禁止输出：

- 保证收益。
- 必中表述。
- 明确鼓励加大投注。
- 绕过购彩限制或平台规则的建议。

## 测试策略

### API 测试

- 体彩玩法解析覆盖 `HAD`、`HHAD`、`CRS`、`TTG` 的真实样本。
- 玩法缺失时返回 unavailable。
- Agent A 输出结构解析成功。
- Agent B 输出结构解析成功。
- Agent C 输出结构解析成功。
- AI 返回无效 JSON 时记录失败日志。
- 不重复生成同一运行结果。

### Web 测试

- 预测任务多选卡能控制执行链。
- 体彩数据卡展示完整玩法。
- 单场组合 Tab 展示保守、均衡、激进方案。
- 串关工作台能选择多场比赛。
- 数据缺失时展示未获取。
- 不出现“稳赚”“必中”“购买建议”“保证收益”等文案。

4. 增加 Agent B 输出结构。

## 验收标准

- 单场预测能输出赛果分析和投注组合模拟两类结果。
- 单个模型能以不同提示词执行不同 Agent。
- 体彩玩法不再只限于胜平负和让球胜平负。
- 数据缺失不会被编造。
- 串关方案基于多场单场方案生成。
- UI 能清楚区分赛果分析、体彩数据、单场组合和串关组合。
- 所有方案包含风险提示和不下注条件。
- 自动测试、类型检查和 lint 通过。
