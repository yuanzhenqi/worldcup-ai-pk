# AI Summary, Leaderboard, and Prompt Weighting Design

## Goal

Improve the match prediction experience so users can quickly understand AI consensus, compare model outputs, see meaningful leaderboard data, and avoid odds-weighted prediction prompts.

## Scope

This design covers three connected changes:

- Match cards show a concise AI prediction summary instead of long execution logs.
- The leaderboard shows both settled scoring and active prediction participation.
- Built-in prompt templates treat odds as page-visible market context only, not as prediction weight.

## AI Prediction Summary

Prediction results on match cards should render as a compact table. The card should show a single summary line above the table:

`AI 共识：主胜 · 推荐比分：2-1 · 主胜 4 / 平 1 / 客胜 0 · 成功 4，失败 2`

The table columns are:

- 模型
- 赛果
- 比分
- 置信度
- 胜负手

Each model row uses the existing parsed prediction fields:

- `modelDisplayName`
- `predictedResult`
- `predictedHomeScore`
- `predictedAwayScore`
- `confidence`
- `shortReason`

The consensus result is generated by majority vote across parsed model predictions. The recommended score is the most frequent predicted scoreline. If multiple outcomes or scorelines tie, display them in a stable order and mark the summary as `分歧`.

The match card should no longer display full execution logs by default. Logs remain available in the history drawer or detail report flow. Failed model count appears only in the compact summary line.

## Report Drill-Down

The existing `查看报告` action remains the path to detailed analysis. The report drawer continues to show:

- Model name
- Predicted score
- Confidence
- Short reason
- Key factors
- Market background note
- Risk points
- Full analysis report

The current `oddsInterpretation` field remains in the DTO and database to avoid a schema migration. In the UI it should be labeled `市场背景`, not `赔率解读`.

## Leaderboard

The leaderboard should be split into two sections.

### 真实计分榜

This section only includes predictions for matches that are finished and have final scores.

Use the existing prediction scoring logic as the scoring source:

- Total score
- Counted finished matches
- Result hits
- Exact score hits
- Recent scores if available

When there are no settled matches, show `暂无已结算比赛`.

### 预测活跃/观点榜

This section does not require matches to be finished. It should show model participation and prediction tendencies from parsed predictions:

- Model name
- Predicted matches count
- Home / draw / away distribution
- Average confidence
- Latest predicted scoreline

This section keeps the leaderboard useful while the tournament has few finished matches.

## Prompt and Odds Handling

Odds may still be displayed in the data drawer, but AI prediction prompts must not use odds as a weight for result, scoreline, or confidence.

Implementation rules:

- Frontend prediction defaults should not include the `odds_interpretation` task.
- Frontend prediction data defaults should not request odds for AI context.
- Built-in prompt templates should remove wording that asks models to use odds to decide an outcome.
- The odds-driven built-in template should be disabled or replaced with a non-default market-background template.
- Prompt rules should state: `赔率只能作为市场背景说明，不得作为胜平负、比分、置信度的判断依据。若上下文含赔率，必须明确其不参与预测权重。`

Existing stored prompt templates are inserted only when missing, so the implementation must also update existing built-in prompt rows by id during seeding.

## Data Flow

Prediction execution can continue storing parsed model predictions in `ai_predictions`.

The public API should expose enough data for the frontend to render:

- Compact per-match prediction summary
- Leaderboard settled scoring rows
- Leaderboard active participation rows

The frontend can calculate the card summary from available run/history data if the API already returns parsed predictions. For leaderboard data, prefer server-side aggregation so the table is stable and testable.

## Error Handling

If prediction history or leaderboard data fails to load, show a concise error state inside the affected section and keep the rest of the page usable.

If a match has parsed predictions but no successful consensus because all parsed data is missing, show `暂无可汇总预测`.

## Testing

Backend tests should cover:

- Leaderboard aggregation for settled matches.
- Active prediction distribution and latest scoreline.
- Built-in prompt seeding updates existing built-in rows away from odds-weighted wording.

Frontend tests should cover:

- Match card renders the consensus summary table.
- Detailed report labels `oddsInterpretation` content as `市场背景`.
- Leaderboard renders settled and active sections, including empty settled state.
- Prediction request defaults no longer include odds weighting options.
